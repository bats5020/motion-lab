# Line Flow — 設計・使い方・検証

2026-09-27。実装の正本は **`tools/line-flow.html`**。Motion Labの最新 `origin/main`（ecc0097）から作成した作業ブランチ `codex/line-flow-20260927` に追加。元の作業ツリーにある未コミット変更には触れていない。

## 目的と現状

線の流れ、多色グラデーション、質感、動きをブラウザで制作し、Webサイトやビジュアルの一部として持ち出すためのツール。添付された9点の参照画像から、太い曲線・ループ・交差・細線の反復・色面・サテン調の陰影・粒感を分解して独自に実装した。ユーザーの追加指示により、文字の作成機能は削除し、手描きと曲線のリファインを主な操作に変更した。

依存ゼロ・ビルド不要の単体HTML。画像生成API、外部フォント、外部アセット、外部通信は使用しない。参考サイトのコード・画像は同梱していない。編集はブラウザ内で完結する。ハブへの登録はこの作業ブランチ上に用意済み。公開版への反映・PR・コミットは未実施。

|---|---|---|
| [fffuel / llline](https://www.fffuel.co/llline/) | 点から有機的な線を作り、太さ・丸み・グラデーションなどを調整、SVG出力 | キャンバス上で点をドラッグする編集。初手で描く必要がない構図プリセットも用意 |
| [fffuel / gggrain](https://www.fffuel.co/gggrain/) | 色・粒感の強さ・周波数などを調整するグラデーション生成 | 線の内側だけに粒感を加える。強さと粒径を別々に調整 |

| [Haikei](https://haikei.app/) | ジェネレーター選択・サイズ・調整・再生成・SVG/PNG出力 | プリセット→調整→書き出しの短い導線。ランダム生成は全体を壊さず選択した線だけ変える |

制作上の狙いは、個別ツールを往復せず **線→配色→質感→動き→出力** を同じ画面で扱えること。既存ツールより優れていると実証したものではない。使いやすさと仕上がりは、実制作でのフィードバックを受けて調整する。

## 使い方

1. `tools/line-flow.html` をChromeで開く。
2. **「手描き」でキャンバスをドラッグ。離すと、細かなブレをならした曲線に変わる。** 選択中の線を置き換えたいときは「描き直す」を使う。描画中にも補正後の線をプレビューする。
3. 「整え具合」で、描いた線に近い状態から大きな流れを優先する状態まで調整。「元の線と比較」で元の軌跡を重ねる。
4. 必要なら編集点をドラッグして仕上げる。点の手動編集後はその形を次のリファインの基準にする。線上をダブルクリックで点を追加、点を選択してDeleteで削除。矢印キーで微調整、Shift併用で10px単位。
5. 配色・質感・動きを調整して、「書き出す」で形式を選ぶ。

プリセットからも開始できる。「配色・質感も適用」を外すと、選択中の線の表面設定を引き継いで構図を替えられる。キャンバスの寸法・モーション設定は維持する。

手描きと点の編集では元の形を表示する。タイムラインや再生・書き出しに切り替えると、指定した時刻の動きを表示する。クリックだけや極端に短い軌跡は線として追加しない。Escapeで描画を中止でき、有効な自動保存は保持する。

### 編集できること

- 8つの構図：Ribbon / Big loop / Interlace / Night drift / Soft wave / Echo lines / Color play / Color fields。
- 手描き：大まかな流れをドラッグして、離すとリファイン。元の軌跡を保持し、補正量を戻しても累積変形しない。マウス・ペン・タッチのPointer Eventsに対応。
- 曲線：太さ、なめらかさ、太さの抑揚、回転、大きさ、左右・上下位置、反転。
- 最大12レイヤー、1本につき2〜64個の編集点。追加・複製・表示切替・前後の入れ替え。
- 配色：8パレット、2〜6色のHEX・位置を編集。線の長さに沿う色／画面を横断する色／色面／単色、色順の反転。
- 質感：フラット、サテン調の陰影、グレインの強さと粒径、不透明度。粒感は線の内側だけ。
- 動き：色の流れ、揺れ、描画、漂い。2〜30秒のループ。描画以外は動きの強さも調整。
- 白・オフホワイト・濃色・任意色・透過背景。横長・正方形・縦長・任意寸法。
- Undo/Redo（最大70操作）、localStorage保存、JSONの書き出しと読み込み。

線の自己交差は終点側が手前。交差箇所ごとに上下を反転する機能は未実装。複数レイヤーに分けて前後を調整する。自由なベジェハンドル編集ではなく、近似した少数の編集点から滑らかな曲線を計算する。手描きの全点を忠実に通る設計ではない。補正を強くすると小さな折れや狭いループが変わる場合があるので、残したい細部があるときは補正量を下げる。

### 出力形式

| 形式 | 内容 | 組み込み方法・制約 |
|---|---|---|
| PNG | 現在のフレーム、背景透過、1×〜3×（長辺最大4096px） | `<img>`、背景画像、デザイン素材として使用 |
| SVG | 現在のフレームの静止画 | 色を短いベクターパスに分割して表現。単一の編集可能ストロークではない。グレインのみ小さなPNGを内包。パス数が多いため用途によってPNGの方が扱いやすい |
| HTML | アニメーションを含む単体HTML | UI・外部依存なし。iframeで配置。レスポンシブ、非表示・画面外の描画停止、`prefers-reduced-motion` 対応 |
| WebM | 1ループ、背景色あり、長辺最大1920px | 実時間録画。Chrome推奨。タブ非表示で中止。透過動画・音声なし |
| JSON | 再編集用の設定 | Line Flowの「開く」で復元。任意SVG・HTMLの読み込みは行わない |

HTMLの例：ダウンロードしたファイルを `/assets/line-flow.html` に配置する。

```html
<iframe
  src="/assets/line-flow.html"
  title="抽象的なラインビジュアル"
  loading="lazy"
  style="display:block;width:100%;aspect-ratio:3 / 2;border:0;pointer-events:none;"
></iframe>
```

背景として装飾に使う場合は、用途に合わせてtitleやアクセシビリティ属性を調整する。埋め込み先がインラインスクリプトを禁止している場合、HTML内のスクリプトを外部JSに分けるなど、そのサイトのCSPに合わせた実装が必要。これは通常のiframe用HTMLであり、すべてのCSP下で動作することを保証するものではない。

SVGやPNGでは動きは保持しない。アニメーションの再利用にはHTMLを選ぶ。MP4/GIF/Lottie、タイムライン上の任意キーフレーム、SVGパスのインポート、真の3Dリボン・照明は今回の実装範囲に含めていない。

## 実装の構成

`createLineEngine()` が描画の正本。UIと書き出しHTMLが同じ関数を使う。`refineStroke()` は手描きの近似処理の正本。

- 手描きを等間隔の弧長サンプルへ再配置→補正量に応じたGaussian平滑化→RDPで少数点に近似。描く速さやイベント頻度の影響を抑え、始点・終点と大きな流れを保持する。出力は最大48点、元の軌跡は最大1024点を保存。
- 正規化された編集点からCatmull–Rom相当の曲線を計算し、弧長に基づいて色を補間。
- 短い丸端ストロークを連続描画。線幅の抑揚と法線方向の陰影で立体感を調整。
- seed付きのノイズタイルを線の内側に合成。時間ごとにランダム値を変えない。
- 動きは0〜1の位相から算出。同じ設定・時刻なら同じフレーム。プレビュー、PNG、SVG、動画は同じ形状計算を利用。
- JSONは既知の値のみを読み込み、数値範囲・色・点数・レイヤー数を検証。読み込み失敗時には現在の作品を維持。
- 自動保存キー `motion-lab-line-flow-v1`。描画中の軌跡は一時データとして扱い、有効な線を確定した時点で1操作として保存。クリックだけ・描画中断では既存の作品を変えない。
- プロジェクト形式はバージョン1のまま、任意の `source` と `refine` を追加。以前のJSONも読み込める。廃止した `text` は読み込み時に無視する。HTMLには手描きの元データを持ち出さず、確定した曲線だけを含める。
- 編集の履歴とプロジェクトの保存は独立。書き出しで編集点やUIを混入させない。

高解像度・多数の線・多数の点・サテン調の組み合わせでは描画コストが上がる。プレビューは解像度と曲線の分割数を抑え、PNGは高い分割精度を使うため、輪郭のアンチエイリアスが完全なピクセル一致になるとは限らない。
