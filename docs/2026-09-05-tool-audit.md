# MOTION LAB 解析・改善記録 — 2026-09-05

## 結論

12ツールの表現領域は広い。次は「作ったものを確実に書き出せる」「後から同じ状態を再現できる」「調整中に重くならない」を優先すると制作に使いやすくなる。

今回の正本は `tools/*.html`、入口の掲載情報は `index.html` の `TOOLS`。最新 `origin/main`（eafc3ef）から `fix/recording-reliability` を作成して修正。以下は9月5日時点の記録。9月16日に実ブラウザで再検証し、公開用ブランチへ統合した（[公開確認記録](2026-09-16-motion-lab-release.md)）。

## 構成と強み

- 素のHTML／CSS／JavaScriptが中心。ビルド不要で各ツールを開ける。
- Canvas 2DとWebGLを表現ごとに使い分けている。Thermal Flowではdirty判定、Halftone Labでは必要時だけの描画ループが既にある。
- シェーダー系、文字系、画像加工系が揃い、単一エフェクトからEffect Stackの重ねがけまで試せる。
- Thermal FlowのUndo、複数ツールのURL設定共有、Effect StackのJSON入出力など、制作を支える機能もある。ただし対応範囲はツールごとに異なる。
- 「依存ゼロ」は全体には当てはまらない。WireframeはCDNライブラリ3種＋GIF worker、Warp TypeはGoogle Fontsに依存する。READMEの説明と掲載漏れ2ツールを修正した。

## 確認できた不具合と今回の変更

| 対象 | 原因・影響 | 修正 |
|---|---|---|
| Glass Lab / Effect Stack / Halftone Lab | MP4をフォールバックとして選ぶが、ファイル名は固定で `.webm` | MediaRecorderの実際のMIMEに合わせて `.mp4` / `.webm` を選択。録画ボタンを「動画録画」に変更 |
| 上記3ツール | captureStream / コンストラクター / start の失敗時にUI・状態・トラックの後処理が不足 | 対応確認、例外通知、トラック停止、タイマー解除、録画状態復元。Effect Stackはサイズ固定解除、Halftone Labは元のアニメON/OFFを復元 |
| U19 Aberration | MediaRecorder対応確認前に録画フラグを立て、開始失敗でフラグが残る | 対応確認、開始成功後の状態更新、開始失敗時の時間復元、WebM VP8候補追加、終了・失敗時の後処理 |
| 修正4ツール | 非同期エラー後の遅いstopイベント、停止処理中の連打、空データの保存 | セッション内のデータ管理、遅いイベントを無視、停止待ちの重複開始防止、空ファイルを保存せず通知 |

形式はMediaRecorderの `mimeType` が表す出力に合わせる。[MDN: mimeType](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/mimeType)。取得したトラックは終了時に明示停止する。[MDN: MediaStreamTrack.stop](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/stop)。

単体HTML構成を維持し、今回共通ランタイムや新しい外部依存は追加していない。

| 低 | ハブの検索・出力形式フィルター | 12ツールになるとRaster / Motionだけでは「透過」「SVG」「動画」を探しにくい。名前検索＋出力形式で目的のツールへ辿りやすくする |

## 決定

新しい表現追加より先に、確認できた保存不具合を修正した。ビジュアルや既存エフェクトの計算式は変更していない。次の大きな更新は、再利用性を高める「素材込みプロジェクト保存」を第一候補とする。
