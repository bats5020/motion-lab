# Thermal Flow — グラデーション・アニメーション編集

2026-09-13。実装の正本は `tools/thermal-flow.html`。ビルド不要、追加ライブラリ不要、ブラウザ内で動作する。PC専用の操作設計。

## 依頼と参照

ユーザーの依頼: [KAGARIBI-15 Gradient Generator](https://kagaribi15-grad.ke-goworks.com/) と同じ制作機能を追加する。各モジュールを実際にONにし、表示された設定・キャンバス操作・書き出し項目を観察した。内部コード・配布素材は使用せず、同種の編集機能を自前で実装する。数値の意味や出力画像の完全一致、参考ツールとのJSON互換は対象に含めない。

参考側のAfter Effects Connectは画面上で「現在開発中」と表示されていた。未提供の連携機能は追加せず、MOVとPNG連番を編集ソフトへ渡せる形式として用意する。

## 操作の入口

- 支給画像のような暗い青緑と赤黄の流体: 先頭の「溶融リボン」「溶融プール」「溶融ウェーブ」。向きを選び、「模様の大きさ・伸び具合・粒感」の3つで調整する。
- 普段の編集: ルック → 配色 → 主操作 → PNG保存。
- グラデの形・色を編集: 配色バー、または「グラデーションを編集」。ステージ上部の「グラデを編集」でハンドルも表示。「パネルを分離」で位置と大きさを変えて使える。
- 効果を重ねる: 「エフェクトを追加」を開き、使うモジュールをON。OFF時には各設定を隠す。
- 動き: 「モーション」をONにし、「タイムラインを開く」。各数値の◇ボタンで、その項目のキーフレームを追加。
- 保存: マスク使用中の静止画は外側の余白を自動トリミング。画像は右下、JPG／WebP／連番／MOVは「•••」。編集可能な作品は「作品を保存・読み込む」。

## 描画・保存の注意点

- 追加効果は初期状態ですべてOFF。既存ルックを選ぶと、追加の形・効果・キーフレームも初期状態へ戻る。画像と保存ファイル名は保持する。
- グラデ編集・手描き編集・渦編集は同時に操作対象にならないよう切り替える。
- ブラシの変形は操作点を記録し、変位テクスチャとして描画する。最大1000点、ベジェは最大4本。
- SVG読込は最初のパスの輪郭を4本の編集可能なベジェ曲線に近似する。SVG内のスクリプトや外部素材は実行・読み込みしない。複雑な複合SVGをそのまま再現する用途ではない。
- Lab／LCHはD65白色点。RGBへの変換で表示範囲を超えた値はクリップする。
- 画像を含む作品の持ち運びはJSONを使う。設定URLには元画像を含めない。
- ブラウザ内保存の容量を超えた場合はJSONで保存する。作品名はHTMLとして解釈せず文字列として表示する。
- 連番とMOVは、指定fpsの時刻を順番に描画する。WebMの実時間録画とは出力処理を分ける。PNG連番の終端に始点と同一のフレームを重複して追加しない。
- MOVはPNGフレームをQuickTimeコンテナに格納する。透過を保てるが、再生ソフト側のPNG動画コーデック対応が必要。
- フレーム出力はメモリ内で組み立てるため、圧縮画像の合計512MBを上限とする。キャンセルやエラー時は途中のファイルを保存しない。
- 画像の色分布はプレビューを縮小して測定した近似値。

## 2026-09-13 追加判断: 溶融する流体グラデーション

支給された抽象背景を観察し、暗い青緑の広い面、赤〜黄の発光する帯、太い溜まりから細く絞られる境界、細かな粒感を制作目標にした。支給画像自体はツール内の素材として使用していない。

- 低周波の二段ドメインワープに、独立した拡大率・回転・中心位置を追加した流体モード。従来のグラデーションの描画は維持する。
- 「溶融リボン」「溶融プール」「溶融ウェーブ」と共通配色「ダークサーマル」を追加。先頭の6ルックに3つを置き、その他も「すべてのルック」から選べる。
- 流体モードの主操作は大きさ・伸び具合・粒感の3つ。大きさは模様そのものを拡大し、伸び具合は丸い溜まりから細い帯まで変える。操作順に依存せず、リセットで選択時の形に戻る。
- 「グラデを編集」では移動・向きをキャンバス上でドラッグできる。詳細な拡大率・中心座標と角度はグラデ編集内に置く。
- 粒感「トーン」は明るさに応じて振幅を変え、暗部が灰色に浮くのを抑える。溶融ルックではこのモードを選ぶが、量の初期値は他のルックと同じ0。
- 3:2（1500×1000）をキャンバスに追加。`?p=溶融リボン&size=32` で横長の出発点を開ける。編集中のルック切り替えではキャンバスサイズを維持する。
- 拡大率・角度・伸び具合はキーフレーム対象にもでき、設定URL・作品JSONで復元できる。

## 2026-09-13 追加判断: マスク保存時の自動トリミング

マスク使用時に余白を切り詰めて保存したいという依頼に対応。適用先はPNG（1倍・2倍・4倍）、JPG、WebP、画像のクリップボードコピー。

- 「文字・画像で切り抜く」の文字／画像マスクと、「画像を重ねる・マスクに使う」の画像マスクを対象にする。マスクが有効なら自動適用し、追加設定は設けない。
- 最終出力の解像度で不透明度が0より大きい画素の外周を測定する。薄い輪郭も含め、周囲に完全な空白行・列が残らない矩形に切り詰める。
- 背景色を付けている場合は、背景を除いた描画で範囲を測り、背景付きの画像をその範囲で切り出す。重ねた画像やグローの描画も測定対象に含める。
- プレビュー、キャンバスサイズ、マスクの配置、編集履歴は変えない。ファイル名と保存完了メッセージには実際の画像サイズを使う。
- 保存欄には「マスク外の余白を自動トリミング」と表示する。マスクが空、または元画像がない場合は内容の確認を促し、空画像やマスク未適用の画像を保存しない。
- 透過境界の読み取りは128行ずつ行い、大きい画像で追加の全画面RGBAバッファを作らない。

## 2026-09-14 — 四隅から中央へ伸びるフレア

mao支給の対戦カード参考画像（2026-09-14 14.48.53）を観察し、中央に暗い余白を残す「四隅フレア」を追加。四隅をそれぞれ起点に、キャンバスの縦横比に応じた中央方向へ炎を生成する。角ごとに異なる連続ノイズで輪郭をうねらせ、鏡像の反復を避ける。画像・ロゴ・参考元のコードは取り込まず、既存WebGLシェーダー内で生成する。
